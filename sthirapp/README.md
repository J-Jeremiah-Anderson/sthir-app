# Sthir — financial resilience for gig & informal workers

Prototype: verifies proof of income, scores financial resilience, warns before a
cash crisis, offers responsible advances (and protective refusals), and routes
emergencies to free government cover before any loan. Two portals (worker +
lender) served by one FastAPI backend. All money is simulated.

Live demo: https://sthir-production.up.railway.app

## Run locally
```bash
cd sthir
python3.12 -m venv .venv          # 3.11 / 3.12 recommended (not 3.14)
./.venv/bin/pip install -r requirements.txt
./.venv/bin/python -m app.seed    # seeds 4 workers, 7 sources, 65 income events
./.venv/bin/python -m uvicorn app.main:app --port 8000
```
Open http://localhost:8000/ — landing page links both portals.

- Worker portal: `/worker.html`   Lender console: `/lender.html`   API docs: `/docs`
- Demo logins: any worker phone (e.g. `+919600012345` = Ravi) or admin
  `admin@sthir.in`; password for all: `sthir2026`

## Optional: real AI photo extraction (Gemini)
Set a Google AI Studio key; the app auto-detects it and reads uploaded
invoices/payouts/bills. Free tier: use a flash-lite model (already the default).
```bash
export GEMINI_API_KEY=your_key
```
Without a key it falls back to a deterministic offline extractor.

## Deploy (Railway)
```bash
railway init && railway up --service <name>
railway domain --port 8080
```
`.python-version` pins 3.12; `Procfile` / `railway.json` seed then start uvicorn.

## Layout
- `app/` — FastAPI backend (models, services, main), `app/services/` has the
  resilience, credit, distress, entitlements, crisis, verification engines
- `web/` — the two portal SPAs (React via CDN, no build step) + landing page
- `API.md` — endpoint contract · `CHECKLIST.md` — QA checklist
- `data/` — seeded evidence images (regenerated by `app.seed`)

Files named `*_fabricfund.bak` are old backups from an earlier name; safe to delete.
